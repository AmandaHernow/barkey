Privacy Policy

Last updated: October 29, 2026

This policy describes the personal Android version of BarKey, package net.hernow.barkey. BarKey is a camera-based keyboard that scans barcodes and inserts their decoded text into the active field. It does not describe other applications or any separately maintained enterprise build.

Camera access and scanning

BarKey requests Android Camera permission to display the rear-camera preview and scan codes. Camera frames are analyzed locally on the device with ZXing-C++ and a ZXing Core fallback. Camera frames and decoded barcode contents are not uploaded to a server.

Camera use starts while the scanner keyboard is active and stops when the keyboard is hidden, input ends, or the in-keyboard Help panel is opened. You can deny or revoke Camera permission in Android settings; scanning then remains unavailable until permission is granted.

Keyboard and editor context

BarKey is an Android input method. You must explicitly enable it in Android keyboard settings and select it yourself. Android displays its standard input-method warning because a selected keyboard can interact with the focused text field. BarKey uses Android’s InputConnection to insert scans and perform the editing actions you request.

For Backspace and guarded Undo, BarKey may request bounded text around the cursor and selection information to verify that an operation is safe. It initially requests up to 16 characters on either side. Undo can temporarily hold the latest inserted text and a bounded snapshot of nearby editor context in memory. Password/private fields are excluded from scan Undo. The receiving application controls its editor implementation and may limit what context is available.

Temporary data, storage, and retention

  • Decoded text is temporarily held in memory while it is decoded and inserted into the focused field.
  • Duplicate suppression retains the most recently accepted scan value in memory until the active input session ends and compares repeated values during a one-second window.
  • Guarded Undo may retain the latest BarKey insertion and bounded surrounding cursor context in memory while it remains safely undoable.
  • The duplicate-suppression value is cleared when the input session ends. Undo context is cleared when the input session ends, the keyboard is hidden or switched away from, or relevant editor context changes. BarKey has no permanent barcode history and does not write scan values to logs or persistent app storage.

Text inserted by BarKey becomes part of the destination field controlled by the app you are using. That app may store or transmit the text according to its own behavior and policy.

Information we collect

BarKey does not require an account or login and contains no analytics, telemetry, advertising, advertising identifiers, or tracking SDKs. It does not collect or upload barcode values, camera frames, or editor text. The app does not include crash-reporting or analytics services.

The Android manifest does not request Internet permission or network-state permission. BarKey’s scanning and barcode decoding do not require an internet connection. Camera and editor errors may be written to Android’s local system log for troubleshooting; decoded values and camera frames are not logged.

Links opened by your choice

BarKey may offer links to this policy, About information, GitHub, related projects, HernowNet, or PayPal. The app opens an external link only after you tap it, using an Android browser or another app that handles the link. The destination service then handles the visit under its own privacy practices. The locally bundled PayPal QR image itself makes no network request.

Optional PayPal donations are voluntary and are not purchases, subscriptions, or a requirement to use BarKey. Donations provide no features or benefits. BarKey does not contain a billing SDK.

Children

BarKey is a general-purpose scanning keyboard and is not specifically directed to children.

Changes to this policy

If BarKey’s data handling changes, this policy will be updated here with a revised date. The current policy applies to the personal Android BarKey application identified above.
